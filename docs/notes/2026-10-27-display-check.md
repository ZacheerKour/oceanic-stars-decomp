## 2026-10-27 display check
**Letterbox, scale modes, filter and 60 fps pacing verified on the OpenGL renderer; `settings.ini` display values now fall back instead of aborting; hold-to-fast-forward moved off Tab.** Build of the gfx15 display code, OpenBIOS, `SDL_AUDIODRIVER=dummy`, hidden window, title menu captured with the script `DUMP` action (`win_<tag>.png` = composed backbuffer), window resized with `PSXRT_WINDOW_AT=3200:WxH`.

- **Geometry (fit, linear).** Measured picture extent in the capture: 1280x720 -> 960x720 at x 160..1119; 1920x1080 -> 1440x1080 at x 240..1679; 2560x1440 -> 1920x1440 at x 320..2239; 3840x2160 (render_scale 4) -> 2880x2160 at x 480..3359. Aspect 1.333, equal bars, nothing non-black one pixel outside the picture (no edge bleed). `integer` at 1920x1080 -> 1280x960 (4 x 240), bars 320/60; at 1000x700 -> 640x480. `stretch` -> full 1920x1080. `filter = nearest` captures differ from linear over the whole picture (`antialiasing = false` reaches the present).
- **Internal resolution.** The runtime does render the GPU pipeline at N x native (`render_scale` 1..8 -> `[video] supersampling`; log "internal scale 4x") and downsamples to the window; it is not only a 1024x512 VRAM blit. Widescreen is not offered: the picture is always 4:3 (SO2 draws 4:3 and no widescreen hack exists for it).
- **Pacing.** Visible window, `PSX_FPS_TELEMETRY=1`, window title read from outside: `Game 60 fps 1.00x, Present 59.9 fps, 0 hitch, max 16 ms` on a 165 Hz panel. The runtime logs "wall-clock pacer (16.6834 ms/frame); synchronized swaps on 165 Hz panel", i.e. 59.94 Hz guest (NTSC) is held by the pacer and the 165 Hz panel is not matched. A hidden-window run is paced too: 1000 scripted frames = 8.34 s, but the script frame counter ticks twice per vblank (pad hook), so that is 59.95 Hz, not 120. Limits: one title-menu scene, one sample, no tearing/stutter inspection by eye, no 50 Hz (PAL) disc.
- **Defects fixed.** (1) `play.ps1` accepted `window_width` 320..639 but the runtime rejects below 640 (fatal game.toml error): range is now 640..7680. (2) A bad value for any display key aborted PLAY; it now falls back to the default, prints a note and writes `play\settings.warn`; values are case-insensitive. (3) The runtime's hold-to-fast-forward default is Tab, which is also the L2 key here, so pressing L2 sped the game up: `config.ini` now has `Turbo = F2` (F3 still toggles). Hold is also ignored while the window lacks focus (runtime).
- **Not verified:** a real fullscreen toggle (Alt+Enter/Ctrl+F/F11; the scripted key table has no F11 and a hidden window cannot go fullscreen), a physical 4K monitor, that Tab no longer fast-forwards in a real session (the `Turbo = F2` line is read by the runtime's keymap code, not run), `scale_mode` on the software or Vulkan renderer.
