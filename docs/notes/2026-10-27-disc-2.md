## 2026-10-27 disc 2
**Result: the game's disc swap works in `recomp/rtfull` through the runtime's own lid path, and disc 2 is fully reachable: booted from disc 2 (SCPH-5501 LLE, headless) the game reaches the title, New Game shows "Please insert DISC 1", a scripted lid cycle to disc 1 makes the game re-read the TOC at LBA 300 and continue into Sound Select, character select and the Milokeenia field.** Reinserting the wrong disc first shows the game's "W..." (wrong disc) message and keeps waiting; the right disc then passes. `disc_speed = "instant"` hangs at boot on both discs; "1x" and "2x" work.

**How the game addresses discs** (static, `python -I analysis/disc_map.py [--str]`, `SO2_DATA=<main checkout>`; every exe/program instruction it cites is checked against the bytes):
- No file system: the boot exe seeds slot 0 with CdlLOC 00:06:00 (LBA 300, `0x80011c44`), reads 12 sectors there and decrypts the TOC (`0x80011c20`). `seek(ctx,i)` (`0x80011654`) copies the 4-byte slot as the CdlLOC for CdlSetloc, so every LBA is **absolute on the disc in the drive**. Each disc carries its own TOC at LBA 300 (disc 2 has no SO2.BIN directory record, it does not need one). Both TOCs fit their disc (disc 1 ends at 222881 <= 236531 sectors, disc 2 at 293892 <= 307542).
- Mapping: 4136 indices have identical bytes on both discs, 4126 of them at the same LBA (the two discs share the layout up to the per-disc data). Disc-2-only/changed indices: 7, 4512-4522, 4582-4585, 4587-4604; disc-1-only: 6, 4504-4511, 4563-4572.
- Disc identity = which marker slot is non-empty: `disc_is(ctx,n)` (`0x80011d38`) returns `size(slot n+5) != 0`. Disc 1 has slot 6 (LBA 380: "1:このDISCはStar Ocean - The Second Story - DISC1です。"), disc 2 slot 7 (same LBA, "2:...DISC2..."). No GetID/serial check: the game never looks at SCUS_944.21/.22 or the license string.
- Swap prompt (same routine in program A `0x8003c5ec` and program C `0x8006f958`; graphics from TOC slot 0x11, so no text strings): `cd_stop` (`0x80011d78`: Setmode 0, CdlStop), then loop: `lid_wait` (`0x80011e24`: Getstat until ShellOpen 0x10 set, then until clear), `disc_ready` (`0x80011eb4`: up to 1800 VSyncs for motor-on, GetTN, ReadS at LBA 300, then re-read + decrypt the NEW disc's TOC), `disc_is(wanted)`; wrong disc -> message 5 and loop; 0/2 -> messages 7/8. Callers: A `0x800422b0`, `0x8003d23c`, `0x8003e12c` want disc 1 (New Game/Continue from disc 2); C `0x80048b4c`/`0x80054260` want `*(u8*)(*(u32*)0x80075270 + 0x4c) + 1` (the game-state disc number, 0 = disc 1), C `0x80052e14` calls the prompt with it.
- So the runtime only has to do what a console does: open the lid (Getstat shows 0x10), swap the image, close it. psxrecomp's `psx_disc_tray_cycle` (2 s timed close, ShellOpen latched until a Getstat acknowledges it) matches `lid_wait` exactly.
