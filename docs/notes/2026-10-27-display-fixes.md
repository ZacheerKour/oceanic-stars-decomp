## 2026-10-27 display fixes (beads 2gi, qqr)
- **2gi borderless alt-tab.** The runtime's borderless mode (`window_fullscreen.h`, mode 1) is already a plain popup window, not SDL fullscreen: no video-mode change, no exclusive ownership, no topmost. But it was sized to exactly the monitor (3440x1440), which Windows and the GPU driver promote to fullscreen (flip presentation / display ownership); that matches monitors blanking on alt-tab. Fix (CMakeLists.txt patch): the window is one row short of the display (3440x1439) at the display origin, so it stays an ordinary desktop window. Same path for `window_mode = borderless` and the menu/Alt+Enter toggle. Evidence: hidden run `qs_display_borderless.txt` -> `win_borderless.png` is 3440x1439 (`[psxrt-gfx] ... fullscreen 1, window 3440`). Not verifiable headless: real alt-tab on the user's monitors. Test: set borderless, alt-tab away and back several times, and Win+Shift+Arrow between monitors; the bottom pixel row shows the desktop.
- **qqr menu stretch.** The F10 panel is a 640x480 image drawn over the whole window (`gl_draw_osd_image(..., ww, wh, ...)`), so on 3440x1440 the pixel font was ~5.4x wide by 3x tall. It is now drawn in a centred 4:3 box (`PSXRT_DRAW_MENU`, `stubs/psxrt_video.h`), whatever the window or scale_mode. Evidence: `qs_display_menu_win.txt` with `PSXRT_WINDOW_AT=12300:3440x1439` -> the panel is 1919x1439 centred (x 760..2679), 3x square pixels.
- **Picture vs scale_mode** (3440x1439 window, `qs_display_pic.txt`, one run per mode, sequential: parallel runs collide on `mods\state.toml`): fit 1918x1439 centred (4:3); integer 1600x1200 (5 x 240 rows, centred); stretch 3440x1439. All behave as documented; no change needed.
